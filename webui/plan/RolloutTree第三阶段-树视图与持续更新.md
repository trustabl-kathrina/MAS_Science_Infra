# Plan

本阶段交付某次训练下的“采样结果”页面：左侧选题目，右侧默认阅读回答卡片；需要研究生成来源时，用户主动切换到树状“分支关系”；点击任一回答后展开同一份详情。

这不是取消树状 UI，而是让用户先看懂回答，再按需查看关系。底层继续使用 RolloutTree，页面不照搬其对象层级，不要求用户理解 tree、group、node 和 snapshot 才能阅读结果。代码已接入，核心快速检查与生产编译通过；真实服务器数据与浏览器视觉验收仍待完成，具体范围见 Implementation Notes。

主要依据为 [new_framework 设计](../../docs/New_framework_design.md) §2.7，语义见 [实施总览](RolloutTree实施总览.md)，依赖 [第二阶段](RolloutTree第二阶段-结果回填与按运行读取.md) 的持久结果与只读接口。

## Position in the Project

这是三个阶段的第三阶段。技术模块仍为 RolloutTree，面向用户的入口与页名统一为“采样结果”，视图按钮统一为“回答列表 / 分支关系”。不新增与 MAS、Monitor 平级的全局技术入口，不重做 Workflow/Sampling 编辑器，也不把独立调试记录当作训练过程。

```text
实验 → 某条训练记录的 [采样结果]
     或当前查看的训练控制台 [采样结果]
       → 固定 run 的结果页
         → 左侧选题目
         → 回答列表（默认） / 分支关系（用户切换）
         → 点击回答，展开详情
```

## Requirements

- 页头用紧凑标题行显示“采样结果”、算法与运行状态，次行显示运行时间与可展开的运行信息。沿用工作区已有的“返回实验”，不再增加“返回训练记录”；训练记录作为普通辅助入口，与查看日志、本次配置并列。
- 默认两栏：左侧题目记录，右侧回答列表；未选中回答时不占用空详情栏。
- 不论是否有分支，首次进入默认回答列表；树状“分支关系”始终是用户可选择的另一种视图，不随后台数据自动切换。
- 列表与树共用数据、稳定身份与选中状态，点击同一回答打开同一份详情。
- 回答卡片优先显示编号、执行状态、最终奖励、生成来源和两三行答案摘要。
- query 主要呈现为题目标题；底层根节点不必机械地画成一张大卡片。
- 已完成父 rollout 产生 child 后仍显示自身结果。
- planned、运行失败、未确认终态、缺结果、无树产物都有独立提示。
- 不改变 Workflow 草稿，不在结果页启动训练、编辑模型或重新执行分支。
- 沿用已有视觉 tokens、按钮、提示和布局；树只读、自动布局。

## Scope

- In：固定 run 入口与地址、分页题目记录、回答卡片列表、只读分支树、按需详情、持续轮询与故障恢复。
- In：已有结果与来源展示、复用“本次配置”只读快照、查看来源回答。
- Out：全量消息树、通用 Trace 平台、树编辑、自动奖励归因、新 SSE 回放系统。
- Out：新建历史 Workflow 图形定位、完整训练 Trace 阅读器、全量关键词搜索及奖励排名系统。不能提供尚无可靠数据支持的按钮。

## Current State

- 新 WebUI 没有 RolloutTree 页面；旧全局接口不得用于新页面。
- 现有 `TrainingHistory`、`TrainingConsole` 可提供固定 run 入口。
- `TrajectoryDetails` 是单题执行视图；其调试 run 路由不能接受训练 Store rollout ID。
- `@xyflow/react`、统一反馈与轮询 hook 已有，应复用，不另建绘图库或全局 store。
- 当前训练记录已有“查看日志 / 本次配置”；控制台是底部可调整高度的阅读区，不适合容纳完整的题目、答案和分支树。
- 当前工作区页头突出实验保存、GPU 和启动训练；历史结果页应明确只读运行上下文，不能让这些草稿操作看起来会修改历史结果。
- 第二阶段 API 已提供按 run 的摘要、答案摘要、分支来源、判定与分页，但不等于完整训练 Trace 已可访问；现有“本次配置”是只读配置弹窗，不是历史 Workflow 画布。
- 现有接口支持训练/验证与精确 task_id 筛选，尚无全量题目关键词搜索、失败筛选和奖励排序。

## Proposed Architecture

### 页面组合

新增 `features/rollout-tree`，按 API、只读查询状态、题目列表、回答列表、分支图和共用详情拆分必要模块，不为两种视图维护两套结果状态。页面负责组合，图布局不进入 API 类型，后端不存像素坐标。

训练记录上的入口：

```text
ARPO · 09月28日 10:20 · 已完成
[采样结果]    [查看日志]    [本次配置]
```

结果页占据工作区主体，不叠在 Workflow 编辑画布上，也不嵌入底部日志窗口。进入结果页时不自动展开控制台；用户点“查看日志”后才打开同一 run 的既有控制台，返回时保留结果页阅读状态。

### 默认页面：选题目，读回答

以下内容均为界面示意，不作为页面缺数据时的默认值。

```text
采样结果  ARPO · 已完成          [训练记录] [查看日志] [本次配置] [刷新]
09月28日 10:20 · abc123…（可展开运行信息）

题目记录                         某道数学题的题目内容……
[训练 / 验证]                    [回答列表] [分支关系]

▌某道数学题……                    回答 A        执行已完成 · 最终奖励 0.4
  4 次生成 · 2 次来自分支          独立生成
  本次采样辅助标识                “这里是两三行回答摘要……”
                                                        [查看详情]
  另一道题……                     ──────────────────────────────────
  3 次生成 · 无分支                回答 B        执行已完成 · 最终奖励 0.8
                                 从回答 A 的中间位置重新生成
                                 “这里是另一次回答摘要……”
                                                        [查看详情]
                                 ──────────────────────────────────
                                 回答 C                      执行失败
                                 从回答 A 的中间位置重新生成
                                 未记录最终答案
[上一页] [下一页]                                       [查看详情]
```

- 左侧突出题目内容摘要、实际生成数与分支数；长串 tree/group ID 不作为标题。同题不同采样组通过训练/验证、记录时间和辅助标识区分，不偷偷合并。
- 首次无深链接选择时可选中第一页第一道题，但不自动选“最佳回答”或展开详情。空列表有独立空态。
- 主区域默认紧凑回答卡片，而不是要求横向阅读许多技术列的复杂表格。答案摘要无需点击即可读到，长内容不撑满整个页面。
- 界面中的“回答”指一次实际生成记录；即使失败没有答案，也保留这条记录并显示“未记录最终答案”，不把它隐藏。
- 回答使用短显示名，列表和树中一致；真实 ID 保留在技术详情。A/B 仅是示意，实施可用稳定短 ID 标签，不按奖励、筛选或当前分页索引反复编号。
- 来源表达区分“独立生成”“独立补采样”“从回答 A 的中间位置重新生成”。来源无法确认时说明未记录，不默认归为独立生成。
- 已完成的父回答产生分支后，仍显示它自身的答案与最终奖励。
- 左侧数量与主区域统计只包含实际 rollout，不包含 query 根、计划或图形辅助标记。“已结束”不代表“回答正确”，失败数可能是已结束数量的子集，不设计相互重叠却看起来互斥的进度分段。

### 分支关系：保留真正的树状 UI

用户点击“分支关系”后，只替换主区域的呈现；题目、选中回答和详情不变。

```text
某道数学题……
[回答列表] [分支关系]

                           ┌─ 回答 B · 执行已完成 · 最终奖励 0.8
回答 A · 最终奖励 0.4 ──────┤
                           └─ 回答 C · 执行失败
             从 planner 的工具返回窗口重新生成

回答 D · 最终奖励 0.6（独立生成）
```

- 树图用于解释来源，不是 Workflow 编辑器；复用 `@xyflow/react`，仅提供必要的缩放、平移、展开和适应视图，无拖线、编辑工具箱或可编辑连接点。
- 题目已在主区域顶部显示，query 根默认不绘制成大卡片；各独立回答作为可见起点，属于同一题目的关系由页面上下文表达。底层 query 根不删除。
- 续跑边显示有证据的分支位置，例如“planner · 工具返回后”；只有记录明确时才显示“第 2 次”。缺 Agent 名称时显示已知 Site 或“分支位置未记录”，不能猜测。
- 边表示从父执行中的某个前缀重新生成，不表示父完整结束后接着执行 child。若使用分叉圆点帮助阅读，它只是装饰，不是新的执行节点，也不计入数量。
- 同一父回答在不同窗口产生的 child，不能合成一个看似共享相同快照的分叉点；节点连接按真实来源表达。
- 树卡片显示短名称、执行状态与最终奖励；点击 B 和回答列表点击 B 打开同一份详情。
- 无分支时仍允许用户选择该视图，展示独立起点并标“独立采样，未发生分支”；不制造连线，不自动切回列表。
- 待关联父节点的记录单独提示“来源待确认”，不当作独立根。只加载部分节点时标明覆盖范围，可见叶子不等于真实叶子。
- 未入队计划放在题目级“未执行的分支计划”折叠区，不画成失败回答或已执行节点，不作为默认主内容。

### 回答详情：点击后才出现

```text
回答 B                              [展开阅读] [关闭]
执行已完成                           最终奖励 0.8

回答内容
这里显示已记录的答案……
内容截断时明确提示，不伪装成完整答案。

生成来源
从回答 A 对应执行过程的一个中间位置重新生成，
不是把 A 的最终答案作为输入。
分支位置：planner · 工具返回后
                                         [查看来源 A]

▸ 训练判定
▸ 技术详情
```

- 无选中项时只有题目列表与主内容两栏；宽屏点选后可形成三栏，详情可关闭、可展开阅读长答案。
- 关闭详情保留主区域的列表滚动或树视口；从图切回列表也不丢失选中回答。
- “查看来源 A”选择同一题目记录中的实际 parent；若当前未加载，先受控加载，不能用相同显示名匹配其他题目的回答。无法解析时提示来源记录不可用。
- 训练判定折叠展示已有 credit、verdict、训练接纳状态和按需诊断；技术详情折叠展示实际 ID、attempt、Site、Window、快照引用和记录问题。
- `node.reward` 标为“节点 credit”，与“最终奖励”分开。缺失值在展开后说明“未计算/未记录”，默认卡片不反复提示未计算 credit。
- 同前缀候选可通过列表与来源切换阅读；本轮不强制新增独立的并排比较系统，也不将父子奖励差解释为某个窗口的贡献。
- 第一版不默认展示空的“Agent 执行过程”，不将独立调试的 `TrajectoryDetails` 套给训练 rollout；未来只有真实训练 Trace 可访问时再增加过程入口。
- “本次配置”复用现有只读快照弹窗，不承诺图形定位历史分支。没有历史 Workflow 画布时不提供“定位到画布”按钮，更不能跳到当前草稿。

### 状态：一个主状态，加必要解释

| 实际情况 | 面向用户的表达 |
| --- | --- |
| 明确执行成功 | 执行已完成；不等于回答正确 |
| 执行结束，但答案未记录 | 执行已结束 · 答案未记录 |
| 明确执行异常、超时或取消 | 执行失败 / 超时 / 已取消，按实际证据显示 |
| 执行完成，但训练适配拒绝 | 执行已完成 · 训练样本未接纳 |
| run 已结束，rollout 终态未确认 | 结果待确认；详情保留最后已知状态 |
| 只读接口失联 | 页面级“连接中断，显示上次记录”；不改变已知节点状态 |

最终奖励缺失显示“—”并说明未记录，0 仍显示 0。奖励最高不等于正确答案，记录缺失不等于执行失败。Store、执行、训练接纳状态在详情中分别可查，但不把三个原始状态码并列作为主界面。

## State and Navigation

| 场景 | 约定 |
| --- | --- |
| 从历史/控制台进入 | 携带固定 experiment/run；不是“当前活动训练”指针 |
| 首次进入 | 默认回答列表；可自动选题，不自动选择最佳回答或展开详情 |
| 地址刷新 | 恢复 run、tree、视图模式及选中 rollout；具体 hash 格式集中扩展现有 navigation |
| 切换回答列表/分支关系 | 保留同一道题、同一选中项与详情；恢复各自的阅读位置 |
| 同组 reward 更新或新增 child | 保留题目、选择、视口与滚动位置；不自动切树、不按奖励重新排序 |
| 切组或切 run | 取消旧请求，按完整身份核对响应，不显示上组详情 |
| 切换题目 | 保留用户选择的视图模式，清除不属于新题目的回答详情 |
| 关闭/展开详情 | 不重置列表滚动与树视口；关闭后焦点返回原回答入口 |
| 返回工作区 | 保留原编辑会话，不用历史快照覆盖草稿 |
| 只读接口失联 | 保留已加载内容并标陈旧，提供重试；不把全部节点标失败 |
| run 已结束而节点仍 enqueued/running | 显示最后已知状态与“结果未确认”，不假装仍在实时执行 |
| 旧运行没有树 | 明确无此记录，不回退全局历史数据 |

视口等仅保存为有界页面会话状态；刷新仅承诺恢复地址和持久结果，不承诺恢复所有临时折叠状态。

结果页头明确“正在查看某次运行”，不突出“保存实验 / GPU 配置 / 开始训练”等草稿操作；这些操作保留在返回实验后的编辑上下文，不因此重置或丢弃已有草稿。训练仍在运行时，停止操作复用同一 run 的控制台，不新增含糊的全局停止按钮。

## API and Data Boundary

- 只用第二阶段的按 run 列表和详情 API，默认列表每页 20 组，按服务端上限加载。
- 第一次只加载选中组的根/首屏及必要祖先；大树按子树/节点页展开。
- 列表返回摘要，详情按需读取；不为每个列表项挂载 React Flow。
- 诊断未运行、无可比候选、未计算 credit 都是正常缺失态，不能用彩色成功标签替代。
- 第一版只提供真实支持的训练/验证筛选与分页，不新增看似全量、实际只过滤当前页的题目搜索、失败筛选或奖励排序。
- 算法和运行时间来自既有 run 详情；接口没有该字段时明确未记录，不从当前实验配置补成历史值。
- 当前详情按 revision 游标分页，并无任意节点直达接口。深链接或“查看来源”命中未加载回答时，做有界分页定位并提示进度；达到界限仍未找到则显示尚未加载/无法定位，不无限抓取或直接断言记录不存在。后续确需高效直达时再最小扩展读取接口。

## Continuous Updates and Rendering

第一版采用可见页面的有界快照轮询，不新增树 SSE。它提供秒级持续更新，不承诺每条状态事件即时呈现。

- 沿用 `usePollingResource` 的取消和活跃状态机制；建议活动页面每 3 秒读取当前页摘要，详情仅在 revision 变化时更新，最多一个同资源请求在途。
- 页面隐藏暂停；返回、重连、run 终态时重取摘要与选中树。
- 自动更新不跳题、不改变回答选择、不自动打开详情、不自动从回答列表切到分支关系；新结果按稳定顺序追加，用户阅读中的卡片不因奖励变化跳位。
- run 终态后做有限的最终刷新；若仍有记录缺口显示“记录未完整”，不无限轮询或强制改成完成。
- 终态时尚未落盘的结果允许通过手动刷新再次读取，不把“停止自动刷新”误认为服务端绝不再有变更。
- 已有 run SSE 可继续驱动控制台，不在树页再消费并解析所有 stdout。
- 稳定 key 使用实际持久 ID；按 ID 合并变化项，未变节点/边保持引用，节点和详情使用 memo。
- 后端当前只有树 revision；前端按已加载 node ID、parent 和边来源派生拓扑签名，与答案/奖励变化分开。reward、状态、详情到来不重新布局；拓扑变化只更新受影响布局。
- 树组件按需加载，未进入分支关系时不初始化整张 React Flow；两种视图共享查询结果，不重复轮询。
- `fitView` 只用于首次打开该组的分支图或用户点击“适应视图”；实时变化不自动抢视口。
- 选择状态保留在页面/局部组件，不经全局 Context 广播给所有画布；大树仅渲染已加载、已展开范围。
- 若采用节点分页，页面明确当前覆盖范围；统计以服务端全组摘要为准，不能用已渲染节点数冒充全树总数。
- revision 变化导致旧 cursor 返回 409 时，废弃混合版本的分页集合，重取首屏并受控恢复已展开范围与选择。恢复前保留内容并标陈旧，不把不同版本页直接拼在一起。

## UI Layout

- 默认两栏，题目列表窄、回答阅读区宽；只有选中回答才显示右侧详情，不长期预留空白 Inspector。
- 回答列表采用紧凑卡片与清晰分隔，不默认展示复杂技术表格；来源是辅助文案，答案是阅读主体。
- 详情先展示答案与最终奖励，再展示来源；长答案支持“展开阅读”，关闭或返回后恢复原位置。
- 分支关系采用只读自动布局；不使用 Workflow 编辑器的网格、连接手柄和拖线工具箱。
- 窄屏先选题，再看回答，详情以抽屉或独立阅读面板呈现，不把三个窄栏并排。
- 视图切换、回答入口、查看来源与详情关闭均可键盘操作；颜色之外使用文字与图标表达状态。卡片内按钮不与嵌套点击区域冲突。
- 延续当前 Typography、间距、边框和反馈风格，不新增另一套设计系统。

## Acceptance and Delivery Boundary

- 有无分支首次均进入回答列表，不操作树也能读到答案摘要、状态、奖励与来源。
- 点击“分支关系”能看到真正的树状 UI；列表和树中点击同一回答打开同一份详情。
- 没有选中回答时不显示空详情栏；选中后可关闭、可展开阅读，关闭不重置主区域。
- 有分支组能回答“从哪个窗口续跑、实际执行状态、实际结果是什么”；无分支组不会被宣传成分支训练成功。
- 父节点有 outcome 又有 child 时，两个结果都可查看。
- 手动更新、后台刷新或新增分支不改变题目、选择和视图模式，不自动排序或抢视口；旧请求不能覆盖新组。
- 页面刷新、断线恢复、Control 重启后读到同一 run 的持久记录；未知值与失败分开。
- 大树不一次性渲染整个 run；未加载节点、未运行诊断、截断答案均明确标示。
- 当前没有真实训练 Trace 或历史画布时，不展示空的执行过程区域，不提供无效下载和定位按钮。
- 页面操作不暗示修改历史运行配置，不将最高奖励标成正确答案，不将执行完成标成答对。
- 前端使用已有编译与检查工具；真实服务器训练和浏览器验收由用户明确启动，不默认执行。

交付是“能查看分支关系的回答浏览器”，完成 RolloutTree 的记录到展示闭环，不是必须点树节点才能读答案的画布，也不是完整窗口级 credit、全算法训练验收或实时 Harness 平台。没有真实服务器证据时只记录代码完成与待验收范围。

## Risks and Edge Cases

- 全量节点对象重建会使 memo 失效；内容更新和拓扑更新必须分离。
- 选中节点被过滤隐藏时保留详情并提示，不自动选择另一个 rollout。
- 记录更新时间不等于 Agent 当前执行时间；失联时不能显示仍持续进展。
- 题目相同不代表同一次采样，回答显示名相同不代表同一节点；归属和跳转始终使用持久身份。
- 活跃树更新可能使 cursor 失效，必须保留用户阅读上下文并说明刷新，不通过无限补页阻塞页面。
