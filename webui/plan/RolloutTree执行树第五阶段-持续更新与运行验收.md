## Proposed Architecture

### 沿用已有更新方式

复用当前约 3 秒的可见页面轮询与 ETag。只读当前题目及必要节点，隐藏页面暂停，不为每个节点创建独立定时器。

run 结束后做有限的最终刷新；仍缺内容或终态时提示记录不完整，保留手动刷新，不永久轮询。Control 始终只读，不在 GET 中重新运行模型或补写过程。

状态变化不触发布局；新增节点再做局部更新。详情正文按需加载，沿用现有分页和大小限制，不先建设独立缓存、事件重放或全量追踪基础设施。

### 必要验收场景

| 场景 | 应当看到什么 |
| --- | --- |
| 两条 initial rollout，无分支 | 同一 Query 下两条独立执行链，分别结束 |
| 某节点后真实分支 | 前缀只一份，原路径与新后缀分别保留结果 |
| 独立补采样 | 从 Query 出发的新路径，不是假 child |
| 多工具并行 | 局部并行与汇合，不当作采样分支 |
| 执行或 child 失败 | 已执行节点保留，失败位置明确，不删除父结果 |
| 重试及旧来源 attempt | 不串接另一 attempt 的前缀 |
| 模型未返回 reasoning | 仍可读真实普通输出，不补造思考 |
| 内容截断或读取失败 | 明确提示，不将摘要称为全文 |
| 刷新、重连、Control 重启 | 同一树与节点内容仍可读取 |
| 旧 v2 记录 | 回答来源仍可读，说明未记录执行过程 |

采样门控未通过是正常结果，不要求每次测试都出分支。验证续跑链时，可使用用户明确认可的独立验收配置，选择确实调用工具的样本；不能暗中修改正常实验的概率或强制输出工具调用。

### 完成标准

一份真实运行应同时证明：

- 图上的执行节点对应实际调用，详情内容不是示例。
- 至少一条实际 child 使用记录中的快照继续生成；共享前缀和新后缀连接正确。
- 原路径与 child 的结果都能查看。
- 原有真实训练 triplet 与参数更新链路不因新增记录而改变。

基础运行还需覆盖无分支情况；不为了有分支而修改原来的判断规则。交付说明分别写清训练是否完成、分支是否发生、过程是否保存，不将它们混为一个成功状态。
