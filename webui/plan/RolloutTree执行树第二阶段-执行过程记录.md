# Plan

在真实调用处记录 Agent/Tool 每次执行的内容，为树节点提供可以阅读的过程，而不是只有最终答案。

状态：代码已接入，核心记录与恢复检查通过；实际 provider 内容待服务器验收。依赖 [第一阶段](RolloutTree执行树第一阶段-节点与数据结构.md)。本阶段不改变提示、分支概率、采样预算或训练奖励。

## Requirements

- 调用开始时分配节点 ID，结束或失败时更新同一个节点。
- 保存本次实际输入、模型原始可见输出、返回的推理字段以及工具交互。
- child 只记录新执行的后缀，不把继承消息再次记录成实际执行。
- 复用 Archive 和已有结果传递方式，不新增审计服务或通用事件系统。

## Current State

`runtime.append_events_from_messages()` 在 episode 结束后转换消息，不能准确表示每次实际调用，也可能包含继承前缀。普通消息序列化不保证保留 reasoning 字段。因此必须在模型/工具调用处记录，不能仅靠最后的 messages 列表补树。

## Proposed Architecture

### 模型执行

在 `call_model()` 内记录：

1. 本次实际使用的消息：在裁剪、finalize 提示等处理之后保存。
2. 调用结果中的普通内容、独立 reasoning、tool calls 和已有 usage。
3. 执行状态、耗时和异常；必要的 HTTP 重试记录在同一执行节点详情中。

不只保存 `<answer>` 中的答案。模型没有返回独立推理字段时，正常展示普通输出；不推断内部思考。现有兼容逻辑生成的回退文本，要标明不是模型实际返回。

### 工具执行

每次工具调用记录一个执行节点，保存工具名、参数和结果。给模型的 observation 如果经过截断，详情注明它与工具原始结果的区别。

并行工具保留实际分组；当前只有整批工具消息写回后可恢复时，就沿用该边界。不为画图而声称每个并行工具返回后都能立即分支。

### 续跑位置

将现有 Window/Snapshot 与产生它的执行节点关联。分支任务携带来源节点、来源 attempt 和快照引用；child 使用恢复消息后，明确报告其来源，再开始记录新节点。

同一前缀只保留原来的节点。若恢复消息在实际调用前被裁剪，节点输入显示实际内容及裁剪提示，不宣传逐 token 完全相同。

### 分支只保留必要信息

**不建设独立“为什么没分支”功能。** 没有分支时树按实际路径继续，用户可以看到是否执行到了配置的分支节点。

到达并实际评估门控的节点，在详情附带已有评估的 `site_id`、是否通过、实际使用的分数/阈值（若该算法有），以及已有的熵信息。不新增 decision ID、所有出口原因枚举、site 汇总或全流程决策面板。

门控只运行一次，记录它已经算出的结果；官方 ARPO 的概率判断不能当成单纯的固定熵阈值。未进行评估就不填“未通过”。快照缺失、恢复失败或入队异常走现有错误日志，不能伪装成正常门控拒绝。

### 记录方式

在现有 `run_episode`/Archive 路径中增加一个小型记录辅助函数或类，供模型和工具复用。每个节点保存摘要和详情引用，通过现有 Runner 结果/annotation 传小型引用，不传整段内容。

节点开始、结束时保存即可，不逐 token 写盘。Runner 写自己的执行记录，Daemon 负责组装树，不让多个 Runner 同时修改同一树文件。

内容脱敏、限制异常大输出并注明截断；显示用内容与恢复用快照分开读取，不能向浏览器暴露密钥或任意恢复文件。

## Implementation Notes

- 2026-09-28：`execution_recording.py` 是 Runner 使用的记录辅助模块，按 rollout/attempt 在 run 的 `rollout-trees/executions` 下保存原子更新的索引及节点详情。没有另建事件平台。
- 已接入实际 `call_model`、`call_tools`、运行时恢复及 verifier 反馈复跑入口。HTTP 重试属于同一节点，保留失败信息和实际重试输入；兼容回退文本标明来源。工具内部未接入的模型调用不声称已完整展开。
- 详情保存消息级实际输入、普通输出、已返回 reasoning、工具调用/结果和 observation；每份详情内容有 128,000 字符总预算，明确 `content_truncated`，不承诺被截断部分可下载。
- 分支记录来源 attempt、Window/Snapshot、节点和实际恢复消息摘要哈希。哈希只验证声明的恢复来源，不据此合并独立执行。记录门控结果不重新抽随机数。

## Acceptance and Delivery Boundary

单条 rollout 中每次已接入的 Agent/Tool 执行都有独立节点和内容。带分支的执行不重复前缀；输入输出可读，模型未返回的信息不补写。增加记录前后，模型调用、随机抽样次数、分支预算及训练奖励不变。
